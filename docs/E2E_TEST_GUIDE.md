# UPTSLK End-to-End Test Guide

This runbook tests the complete web platform using one bidirectional service between **Kadawatha Centre** and **Makumbura Centre**. Use the fixed service date `24 September 2026` and complete every section in order.

## 1. Before you begin

Start PostgreSQL, the API, and the React application in separate terminals.

```bash
docker compose up -d
cd apps/api && dotnet run
cd apps/web && pnpm dev
```

Open the API Swagger page at `http://localhost:5250/swagger` for the two staff-account requests in section 3. Use the web portal for every other test step.

Sign in with bootstrap administrator email `admin@upts.lk` and password `admin123`.

## 5. Commuter and Stripe booking test

Create one commuter account through the public **Sign up** flow using name `Test Adult Passenger`, email `test.passenger@upts.lk`, and password `Passenger123!`. The registration flow creates an `Adult` passenger profile automatically.

Before paying, open `apps/api/appsettings.Development.json` and set `Payments:Stripe:SecretKey` to your Stripe test secret key, beginning `sk_test_`. Set `Payments:Stripe:WebAppBaseUrl` to `http://localhost:5173`. Save the file and restart the API.

Start Stripe CLI forwarding in a terminal:

```bash
stripe listen --events checkout.session.completed,payment_intent.payment_failed,checkout.session.expired,refund.updated --forward-to http://localhost:5250/api/v1/payments/stripe/webhook
```

Copy the `whsec_...` value printed by that command into `Payments:Stripe:WebhookSecret` in `apps/api/appsettings.Development.json`. Save the file and restart the API before continuing.

### Report the breakdown

1. Open **Operations → Recovery agents**.
2. Select the new incident with summary `Engine fault on scheduled service`.
3. Select **Run recovery agents**.
4. Wait for the workflow to finish. Confirm four agent steps are saved with their reasons, warnings, and timings.
5. Confirm the workflow status is `Awaiting approval`. Agent recommendations are proposals; they do not change the trip yet.

### Approve the recovery

1. Open the generated workflow detail.
2. Enter decision note `Replacement bus and driver confirmed for delayed service.`
3. Select **Approve and apply recovery**.

Expected result:

- The workflow becomes `Completed`.
- The approval record shows who reviewed it and when it was applied.
- The trip uses the approved replacement bus, driver, bay, and revised time shown in the workflow.
- The trip status becomes `Delayed`.
- The incident becomes `Resolved`.
- The workflow detail retains all agent recommendations and the final decision as audit evidence.

## 10. Pass criteria

The test is successful when:

- Both route directions generate and dispatch trips correctly.
- Passenger count affects the Stripe amount and remaining vehicle capacity.
- No passenger selects a seat number.
- Stripe webhook confirmation produces a confirmed QR ticket.
- Dispatch lifecycle data is visible in operations views.
- Agent recovery makes no direct change until a Centre Manager/Admin approves it.
- Approved recovery safely reassigns the trip and records an audit trail.
- A missing replacement bus produces a safe failure without changing the trip.
